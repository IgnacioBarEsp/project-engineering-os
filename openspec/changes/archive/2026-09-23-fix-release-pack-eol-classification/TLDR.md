# Correct release EOL classification — #155

The first official release attempt for the immutable `v1.0.0` tag failed before producing assets because the EOL preflight treated `w/none` as an error. `none` means a file has no line terminators, not that it contains CRLF or mixed endings. Accept it only when both index and worktree report `none`, without rewriting the two historical files. The build and npm jobs load the corrected helper, validator, and tag resolver from the exact protected `main` workflow revision; GitHub Release also loads those validators and the candidate verifier from that same commit. The published package remains built from the unchanged `v1.0.0` tag. Until a channel policy exists, the workflow rejects prerelease versions before creating assets or a GitHub Release.
