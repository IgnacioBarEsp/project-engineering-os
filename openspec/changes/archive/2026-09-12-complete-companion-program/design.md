## Context and decisions

The current application is installed on the maintainer's Windows machine; the native process was left at folder
selection. Browser/service fixtures and the deterministic retrieval measurement from #81 remain valid within
their stated limits. A new change records the residual work without rewriting historical observations.

Native acceptance uses operating-system accessibility and screenshots against the installed executable. The
installer is per-user and unsigned. Security dialogs requiring a person are a real boundary, not a step to
automate away. Captures containing account paths stay local; public records describe synthetic fixtures, observed
steps, hashes and results. Installed editors are opened only against the explicit synthetic folder. An opened
folder does not demonstrate that an AI read it. Unit tests continue to use launch adapters.

The experiment compares parsed full corpus against Companion's retrieved passages. Both receive identical
questions and response instructions, use the same model identifier and settings, and alternate AB/BA over three
repetitions. Five profile subjects each include an answerable and an unanswerable question. References are
frozen before inference and never supplied as an answer key. Raw prompts, answers, usage events, errors and
latencies are retained. Evaluation checks known answer values, exact supporting citations and abstention;
it does not claim expert scientific evaluation. Model settings the selected interface does not expose are
identified, not fabricated. Existing subscription access is optional measurement tooling, never a product
dependency. No credentials enter evidence. No extra paid account or model download is required.

The existing build pipeline seals pinned dependencies and verifies the produced installer. A distributable
build must reference a clean committed tree. Delivery uses a separate Companion tag and GitHub release, leaving
the core release untouched. A static GitHub Pages deployment uses pinned official actions and limited job
permissions; the existing required CI gate is preserved. The public EXE is downloaded and rehashed after upload.

Public visual review records live Awwwards reference URLs, date, interaction and responsive observations, and
the resulting decisions for our original static design. No reference code or assets are imported.

## Recovery and acceptance

Original source hashes are checked across preparation, closing/reopening and reinstalling. Failures remain
recorded until corrected and rerun. Missing local apps are distinguished from an existing app that cannot be
verified. Blocker/Major findings prevent archive; genuine optional limits remain in the debt ledger. Removing
the release or deployment is separate from uninstalling, and neither removes user projects or runtime caches.
